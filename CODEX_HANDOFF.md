# Передача контекста проекта другому диалогу Codex

Этот файл предназначен для продолжения работы после клонирования репозитория на другой компьютер.

## Актуальное состояние 15.10.2026

По новому запросу пользователя реализован **MVP бэкенда посещаемости на C#**.
Главное описание: [ATTENDANCE_MVP.md](ATTENDANCE_MVP.md). Это обновляет более
раннее ограничение «пока не делать авторизацию»: теперь локальная авторизация
реализована, но вся остальная LMS не превращена в полноценный backend.

- Настоящий вход по паролю, HttpOnly-cookie, хеширование PasswordHasher,
  CSRF, отзываемые сессии, блокировка попыток и права по курсам.
- Самодельные JWT, токены в URL и заголовок `X-Lms-Demo-User` больше не принимаются.
- Для удобства возвращены кнопки тестового входа admin/teacher/student:
  только Development и loopback, с серверной проверкой первоначального пароля
  и выдачей обычной сессии. Отключение: `Auth__EnableDemoLogin=false`.
- Начальные локальные пароли: игнорируемый `.local/initial-credentials.json`,
  генерируются один раз в Development. Никогда не печатать их в чат/логи/Git.
- Создание, редактирование, отмена занятий и просмотр истории доступны в интерфейсе.
- Состав занятия фиксируется при создании; изменения зачислений не переписывают прошлые журналы.
- OCR вызывается через защищённый C# шлюз; Python должен оставаться на loopback/закрытой сети.
- Миграции `003_auth.sql`, `004_attendance_mvp.sql`, `005_ocr_gateway.sql`;
  всего 69 таблиц в 10 предметных схемах плюс служебная таблица миграций.
- Проверки: 21 тест API/БД, 43 теста Python OCR, C# проверки и браузерные сценарии.
- Реальные OCR-модели и вузовский CAS не подключены. Остальные старые разделы LMS
  остаются демонстрационными. Отчёты v4 относятся к более раннему состоянию.

## Запуск на новом компьютере

1. Установить Git, .NET 10 SDK, .NET 8 runtime и PostgreSQL 15+.
   API подключения БД использует `net10.0`, исходный клиент остаётся `net8.0`.
2. Выполнить:

```powershell
git clone https://github.com/nikooov4/summer_2026.git
cd summer_2026
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local-database.ps1
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project .\omelea-dev-lms\LmsApi\LmsApi.csproj --urls http://localhost:8085
# В другом терминале из корня репозитория:
dotnet restore .\omelea-dev-lms\LMSDashboardBlazor_context_roles_dynamic_generate\LMSDashboardBlazor.csproj
$env:ASPNETCORE_URLS='http://localhost:5293'
dotnet run --project .\omelea-dev-lms\LMSDashboardBlazor_context_roles_dynamic_generate\LMSDashboardBlazor.csproj
```

3. Папка `.local` не попадает в Git. На новом ПК сначала установите
   PostgreSQL/распакуйте бинарники или настройте `ConnectionStrings__Lms`.
   Подробные команды: `database/README.md`. Открыть `http://localhost:5293/login`.
4. Войти локальным аккаунтом `admin`, `teacher` или `student` по паролю из
   `.local/initial-credentials.json`. Новым пользователям пароль задаёт администратор.

Если порт клиента занят, заменить `5293` и обновить разрешённые origins
локального API (`Lms__AllowedOrigins`) и OCR (`OCR_ALLOWED_ORIGINS`).
Адреса API задаются в клиентском `wwwroot/appsettings.json`.

## Что реализовано

### Учет посещаемости

Основные файлы:

- `Models/Attendance/AttendanceModels.cs`
- `Services/Attendance/AttendanceService.cs`
- `Pages/Attendance.razor`
- `Pages/AttendanceMonitoring.razor`

Реализованы:

- выбор полноценного контекста занятия, а не только смена заголовка;
- журнал группы для преподавателя;
- статусы `Присутствовал`, `Опоздал`, `Отсутствовал`, `Уважительная причина` и служебный статус `Не отмечен`;
- минуты опоздания и комментарии;
- валидация: опоздание требует положительного числа минут, уважительная причина требует комментария;
- поиск, фильтрация, сортировка и массовая отметка неотмеченных студентов;
- сохранение журналов в PostgreSQL и отмена несохранённых изменений;
- завершение и возобновление занятия;
- личная история и показатели студента без доступа к редактированию чужого журнала.

### Мониторинг

Реализованы:

- сводка по занятиям и статусам;
- фильтры периода и состояния журнала;
- контроль завершенных и незаполненных журналов;
- список студентов, требующих внимания;
- автоматический выбор первого проблемного студента;
- ручной выбор другого студента и переход к его истории;
- отдельный персональный вид показателей для студента.

### Административная панель

Основные файлы:

- `Models/LmsAccessModels.cs`
- `Services/Admin/LmsCatalogService.cs`
- `Pages/Admin.razor`

Реализованы:

- пользователи;
- курсы;
- зачисления пользователя на курс;
- тип участия в курсе;
- синхронизация состава курса с занятиями;
- импорт и экспорт пользователей в JSON и CSV.

JSON/CSV сейчас обрабатывается как текст в поле административной страницы. Настоящее чтение или скачивание файлов не реализовано.

## Тестовая модель доступа

Ключевые файлы:

- `Pages/Login.razor`
- `Services/AuthSessionService.cs`
- `Services/Admin/LmsCatalogService.cs`
- `Program.cs`

Поведение:

- `admin` видит все курсы, журналы и административную панель;
- `teacher` видит назначенные дисциплины и редактирует их журналы;
- `student` видит только свои дисциплины, историю и показатели;
- ассистент также может редактировать назначенный журнал.

С 15.10 используется локальная cookie-авторизация. Сервер проверяет активность
сессии и аккаунта на каждом запросе. При смене/сбросе пароля старые сессии
отзываются. Админ может заблокировать вход и задать временный пароль.
Клиентский `localStorage` и тестовый заголовок больше не являются удостоверением личности.
Вузовский вход пока не подключён, см. требования в `ATTENDANCE_MVP.md`.

## Где хранятся данные

- Постоянные данные: PostgreSQL `summer_lms`, локально `127.0.0.1:5433`.
- SQL по документу пользователя: `database/001_document_schema.sql` и
  `002_application.sql` и расширения `003`–`005`, 69 таблиц, 10 предметных схем и представление.
- Подключены каталог, зачисления, занятия, отметки, история изменений и
  черновик ведомости автора. Мониторинг рассчитывается по данным БД.
- `AttendanceService`/`LmsCatalogService` держат клиентскую копию;
  `confirmedEntries` нужен для отмены несохранённого редактирования.
- `PersistentLmsService` загружает данные через `LmsApi`; F5 не сбрасывает БД.
- Миграции и тестовый набор применяются один раз, повторный запуск не очищает БД.
- Фото и задания OCR остаются в собственной SQLite/файлах сервиса.
- Остальные старые демонстрационные виджеты LMS не подключены.
- Пароль, строка подключения и кластер лежат в игнорируемой `.local`.
  На другой ПК данные переносятся дампом, не коммитом; см. `database/README.md`.

## Состояние настоящей авторизации dev-lms

В папках `omelea-dev-lms/Client`, `omelea-dev-lms/Server` и `omelea-dev-lms/Shared` есть более старый контур авторизации:

- PostgreSQL;
- проверка паролей;
- JWT Bearer;
- защищенные контроллеры;
- CAS/МИФИ-интеграция.

Он не нужен для запуска демонстрационного интегрированного проекта и не работает из чистого клона без настройки:

- требуется PostgreSQL;
- отсутствует локальный секретный `Server/Properties/appsettings.json`;
- требуется конфигурация JWT, CAS и начального администратора;
- серверная часть основана на старом `net6.0` и содержит устаревшие зависимости.

Файл `omelea-dev-lms/README_MEPhI_LOGIN.md` описывает желаемую интеграцию, но не означает, что внешний auth-service настроен в текущем клоне.

## Что логично делать дальше

### OCR-интеграция (08.10.2026)

Добавлен отдельный компонент `Components/Attendance/OcrImport.razor` и клиент
`Services/Attendance/AttendanceOcrClient.cs` в основной Blazor-проект.
В журнале преподавателя фото сопоставляется с составом выбранного курса;
после проверки отмечается присутствие, существующие отметки по умолчанию сохраняются.
Обычные кнопки сохранения и отмены журнала продолжают работать.
В админ-панели фото используется для создания студентов и зачисления на выбранный курс;
можно выбрать существующего пользователя, исправить ФИО/логин и исключить строки.
Студентам OCR недоступен. При добавлении OCR конструктор не менялся;
последующее подключение БД изменило только его сохранение.

В FastAPI-сервис добавлены CORS, опциональный `students` в запросе создания задания,
сохранение отдельного состава на каждое задание и передача этого состава реальным адаптерам.
Параметр `students=null` сохраняет прежний режим, `students=[]` означает пустой состав.
Ручное сопоставление использует весь переданный состав, не только первые OCR-кандидаты.
Пути моделей настраиваются переменными окружения; команды есть в README.md.

Важно: веса и исходники реальных моделей не переданы. Демо-режим явно возвращает
фиксированный пример независимо от фото. Реальные адаптеры ограничены заданным составом:
для неизвестных ФИО могут возвращать только пустые области, без текста. Полноценное
извлечение новых ФИО требует соответствующего OCR-движка. Теперь права проверяет
C# API с настоящими сессиями. Python OCR API вызывается через этот шлюз и
должен оставаться в закрытой сети; каталог и отметки LMS в PostgreSQL. Фото и OCR-задания
хранятся на диске/в SQLite. Админский импорт применяется в LMS, не через mock export.

Проверки: Python API-тесты (`attendance-ocr-service/tests/test_lms_integration.py`),
проверки C# (`tests/LmsOcrChecks`) и браузерный сценарий (`tests/ocr_browser_check.py`).
Снимки проверок находятся в игнорируемой папке `document_work/browser_profiles/ocr-checks`.

`attendance-ocr-service` передан как вложенный самостоятельный Git-репозиторий.
В нём есть собственные незакоммиченные изменения интеграции. Не удалять его `.git`
и не добавлять вслепую как gitlink: сначала согласовать submodule или перенос исходников
в основной репозиторий. В рамках OCR-задачи коммит и push не выполнялись.
