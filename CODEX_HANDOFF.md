# Передача контекста проекта другому диалогу Codex

Этот файл предназначен для продолжения работы после клонирования репозитория на другой компьютер.

## Репозиторий

- GitHub: `https://github.com/nikooov4/summer_2026.git`
- Основная ветка: `main`
- Проверка актуального коммита: `git log -1 --oneline`
- Перед началом работы: `git status --short`

## Главная цель проекта

В репозитории находятся два исходных направления:

- `uir-main` - экспериментальный прототип учета посещаемости. Внутри много старых и неиспользуемых частей; его следует рассматривать как источник идей, а не как основной запускаемый проект.
- `omelea-dev-lms` - целевой проект LMS. Новая посещаемость переносилась сюда с сохранением дизайна, навигации и исходного конструктора ведомостей.

Основной интегрированный и запускаемый проект:

`omelea-dev-lms/LMSDashboardBlazor_context_roles_dynamic_generate/LMSDashboardBlazor.csproj`

Это Blazor WebAssembly-приложение на `net8.0` и пакетах ASP.NET Core `8.0.19`.

## Запуск на новом компьютере

1. Установить Git и .NET 8 SDK. Более новый SDK тоже может собрать `net8.0`, но .NET 8 является минимальным понятным вариантом.
2. Выполнить:

```powershell
git clone https://github.com/nikooov4/summer_2026.git
cd summer_2026
dotnet restore .\omelea-dev-lms\LMSDashboardBlazor_context_roles_dynamic_generate\LMSDashboardBlazor.csproj
$env:ASPNETCORE_URLS='http://localhost:5293'
dotnet run --project .\omelea-dev-lms\LMSDashboardBlazor_context_roles_dynamic_generate\LMSDashboardBlazor.csproj
```

3. Открыть `http://localhost:5293/login`.
4. Для демонстрации использовать кнопки `Админ`, `Преподаватель` и `Студент`.

Если порт занят, заменить `5293` на другой свободный порт.

## Что реализовано

### Учет посещаемости

Основные файлы:

- `Models/Attendance/AttendanceModels.cs`
- `Services/Attendance/AttendanceService.cs`
- `Pages/Attendance.razor`
- `Pages/AttendanceMonitoring.razor`

Реализованы:

- выбор полноценного контекста занятия, а не только смена заголовка;
- журнал группы для преподавателя;
- статусы `Присутствовал`, `Опоздал`, `Отсутствовал`, `Уважительная причина` и служебный статус `Не отмечен`;
- минуты опоздания и комментарии;
- валидация: опоздание требует положительного числа минут, уважительная причина требует комментария;
- поиск, фильтрация, сортировка и массовая отметка неотмеченных студентов;
- сохранение и отмена изменений текущего сеанса;
- завершение и возобновление занятия;
- личная история и показатели студента без доступа к редактированию чужого журнала.

### Мониторинг

Реализованы:

- сводка по занятиям и статусам;
- фильтры периода и состояния журнала;
- контроль завершенных и незаполненных журналов;
- список студентов, требующих внимания;
- автоматический выбор первого проблемного студента;
- ручной выбор другого студента и переход к его истории;
- отдельный персональный вид показателей для студента.

### Административная панель

Основные файлы:

- `Models/LmsAccessModels.cs`
- `Services/Admin/LmsCatalogService.cs`
- `Pages/Admin.razor`

Реализованы:

- пользователи;
- курсы;
- зачисления пользователя на курс;
- тип участия в курсе;
- синхронизация состава курса с занятиями;
- импорт и экспорт пользователей в JSON и CSV.

JSON/CSV сейчас обрабатывается как текст в поле административной страницы. Настоящее чтение или скачивание файлов не реализовано.

## Тестовая модель доступа

Ключевые файлы:

- `Pages/Login.razor`
- `Services/AuthSessionService.cs`
- `Services/Admin/LmsCatalogService.cs`
- `Program.cs`

Поведение:

- `admin` видит все курсы, журналы и административную панель;
- `teacher` видит назначенные дисциплины и редактирует их журналы;
- `student` видит только свои дисциплины, историю и показатели;
- ассистент также может редактировать назначенный журнал.

Это демонстрационный клиентский механизм. Кнопки входа создают тестовый токен, который хранится в `localStorage` и разбирается на стороне браузера. Это не полноценная защищенная авторизация.

## Где хранятся данные

- `AttendanceService` зарегистрирован как singleton и хранит занятия и отметки в оперативной памяти браузера.
- Подтвержденные версии журналов находятся в словаре `confirmedEntries` того же сервиса.
- `LmsCatalogService` также хранит пользователей, курсы и зачисления в памяти текущего сеанса.
- Переходы между страницами сохраняют состояние.
- Полная перезагрузка страницы (`F5`) возвращает исходный демонстрационный набор.
- Постоянной базы данных и серверного API для посещаемости пока нет.

## Состояние настоящей авторизации dev-lms

В папках `omelea-dev-lms/Client`, `omelea-dev-lms/Server` и `omelea-dev-lms/Shared` есть более старый контур авторизации:

- PostgreSQL;
- проверка паролей;
- JWT Bearer;
- защищенные контроллеры;
- CAS/МИФИ-интеграция.

Он не нужен для запуска демонстрационного интегрированного проекта и не работает из чистого клона без настройки:

- требуется PostgreSQL;
- отсутствует локальный секретный `Server/Properties/appsettings.json`;
- требуется конфигурация JWT, CAS и начального администратора;
- серверная часть основана на старом `net6.0` и содержит устаревшие зависимости.

Файл `omelea-dev-lms/README_MEPhI_LOGIN.md` описывает желаемую интеграцию, но не означает, что внешний auth-service настроен в текущем клоне.

## Конструктор ведомостей

Исходная логика конструктора намеренно сохранена:

- `Pages/StatementConstructor.razor`
- `Services/Statements/StatementService.cs`

Посещаемость добавлена отдельным модулем рядом с конструктором. Не следует переписывать конструктор без отдельного запроса пользователя.

Технически посещаемость можно позже связать с ведомостью через дополнительный показатель, процент или условие допуска, сохраняя расчет оценок конструктора отдельным.

## Финальные отчетные материалы

Актуальная версия находится в:

`Готовые_материалы/Летняя_практика/v4`

Для каждого студента подготовлены:

- отчет `DOCX` и `PDF` - 25 страниц;
- презентация `PPTX` и `PDF` - 16 слайдов.

В отчетах:

- расширенное индивидуальное задание по образцу `Практика.docx.pdf`;
- по 15 источников;
- внутритекстовые ссылки `[1]`-`[15]`;
- отдельное содержание для каждого участника.

Расхождения между формулировками отчетов и реализацией перечислены в:

`Готовые_материалы/Летняя_практика/v4/Памятка_v4_по_содержанию_и_расхождениям.md`

Главные расхождения:

- часть функций переносилась и адаптировалась, а не разрабатывалась с нуля;
- апробация ручная, полного набора автоматизированных тестов нет;
- данные и административный каталог хранятся в памяти;
- тестовая модель доступа не является серверной защитой;
- JSON/CSV работает как текстовое преобразование, а не полноценный файловый обмен.

## Генерация и проверка документов

Основные сценарии:

```powershell
py -3.13 .\document_work\build_v4_materials.py
powershell -ExecutionPolicy Bypass -File .\document_work\export_v4_materials.ps1
py -3.13 .\document_work\check_v4_materials.py
```

Для генерации нужны Python, `python-docx`, `python-pptx`, `Pillow` и `PyMuPDF`.

Для экспорта в PDF используются COM-интерфейсы Microsoft Word и PowerPoint, поэтому на Windows должен быть установлен Microsoft Office. Готовые PDF уже находятся в репозитории; Office нужен только для повторного экспорта.
