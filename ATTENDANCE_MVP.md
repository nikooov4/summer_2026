# MVP посещаемости на C#

## Что готово

ASP.NET Core API `omelea-dev-lms/LmsApi`, PostgreSQL и существующий Blazor-клиент.
Исходный конструктор ведомостей не переписан; сохранение его JSON-черновика осталось.

- Локальный вход по логину/паролю, хеши ASP.NET Core PasswordHasher (PBKDF2).
- HttpOnly-cookie с серверной проверкой сессии при каждом запросе, срок 8 часов,
  выход, смена пароля и отзыв всех старых сессий при смене/сбросе пароля.
- Администратор задаёт временный пароль и может потребовать его смену при входе,
  запретить или разрешить вход. Новый пользователь без пароля войти не может.
- Ограничение попыток: после 5 ошибок учётная запись блокируется на 15 минут;
  дополнительное ограничение login/change-password по IP: 30 запросов в минуту.
- Проверка CSRF-токена для изменяющих запросов, точный список CORS origins.
- Права проверяет API: администратор, преподаватель/ассистент назначенного курса,
  студент только с собственными записями. Смешанные роли из разных курсов не
  дают доступа к чужим отметкам. Куратор читает назначенный курс, но не меняет журнал.
- Создание, изменение и отмена занятия; серверная проверка версии журнала.
- Состав и ФИО фиксируются при создании занятия. Последующее зачисление,
  исключение или архивирование пользователя не переписывает прежние журналы.
- Сохранение статусов, минут опоздания и комментариев, завершение/возобновление,
  история отметок с автором, временем и источником. Отмена не удаляет данные.
- Добавление, редактирование и архивирование пользователей/курсов, зачисления,
  JSON/CSV-импорт и экспорт. Нельзя оставить систему без администратора с рабочим входом.
- Защищённый C# OCR-шлюз: браузер больше не вызывает Python напрямую. API
  проверяет права и файл, сам собирает состав, сохраняет владельца OCR-задания
  и проверяет строки подтверждения. Применение отметок использует обычное сохранение журнала.

Стандартные механизмы:
[cookie authentication](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/cookie),
[antiforgery](https://learn.microsoft.com/en-us/aspnet/core/security/anti-request-forgery),
[Blazor cookie requests](https://learn.microsoft.com/en-us/aspnet/core/blazor/call-web-api).

## Запуск и вход

Из корня, первый терминал (.NET 10 SDK, .NET 8 runtime для клиента):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local-database.ps1
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project omelea-dev-lms/LmsApi/LmsApi.csproj --urls http://localhost:8085
```

Второй терминал:

```powershell
dotnet run --project omelea-dev-lms/LMSDashboardBlazor_context_roles_dynamic_generate/LMSDashboardBlazor.csproj --urls http://localhost:5293
```

Открыть `http://localhost:5293/login`. Доступен вход по паролю и, только в
Development с локального компьютера, кнопки «Админ», «Преподаватель», «Студент».
Кнопки используют первоначальные пароли на сервере и выдают обычную cookie-сессию:
пароли не передаются браузеру, права и CSRF продолжают проверяться.
Отключение: `Auth__EnableDemoLogin=false`; в Production endpoint не регистрируется.
Если первоначальный пароль тестового аккаунта изменён, используйте ручной вход.
Приём самодельного токена из URL не возвращён.

При первом запуске в Development случайные пароли исходных тестовых аккаунтов
создаются в **`.local/initial-credentials.json`**. Например, используйте логин
`admin`, `teacher` или `student` и соответствующее значение из этого файла.
Файл не попадает в Git. Пароли в чат и публичный репозиторий не копировать.
Это первоначальные пароли: после смены они не обновляются в файле и повторный
запуск не сбрасывает их. Утерянный пароль пользователя сбрасывает администратор.
Почтовое восстановление и отдельное аварийное восстановление администратора пока не реализованы.

Для новой учётной записи админ сначала создаёт пользователя, затем в разделе
«Доступ пользователей» задаёт пароль длиной 12–128 символов. Новый пользователь
со сменой временного пароля попадает на `/account/security`; после смены нужно
войти заново. Собственный пароль меняется по кнопке с ключом в верхней панели.

Не смешивайте `localhost` и `127.0.0.1` между клиентом и API: это разные сайты
для cookie. Локальные адреса по умолчанию используют `localhost`.

## OCR

Python запускается отдельно, только на loopback/закрытой сети:

```powershell
cd attendance-ocr-service
$env:PYTHONHOME = ''
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8010
```

Адрес Python задаётся **на сервере C#**, ключ `AttendanceOcr:BaseUrl`
(переменная `AttendanceOcr__BaseUrl`, по умолчанию `http://localhost:8010`).
В клиентском `wwwroot/appsettings.json` используется `LmsApi:BaseUrl`.
Сам Python-сервис не имеет собственной пользовательской авторизации:
не публикуйте его порт наружу. Пользовательский доступ идёт через C# API.

Реальные веса и исходники OCR по-прежнему не переданы. Демо возвращает
фиксированный пример, а не читает загруженное фото. Подключение моделей:
`OCR_NASLEDIE_ROOT`, `OCR_NASLEDIE_MODELS_DIR` либо переменные `OCR_LEGACY_*`.
В MVP обработка ограничена тайм-аутом, но ещё не переведена в долговечную очередь
с возобновлением после рестарта. Для неизвестных ФИО сохраняются ограничения OCR-движка.

## API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/auth/csrf` | Получить CSRF-токен и cookie |
| POST | `/api/auth/login` | Вход по логину и паролю |
| GET | `/api/auth/me` | Текущий пользователь |
| POST | `/api/auth/logout` | Отозвать текущую сессию |
| POST | `/api/auth/change-password` | Сменить пароль и отозвать сессии |
| POST | `/api/users/{id}/password` | Администратор задаёт пароль |
| POST | `/api/users/{id}/access` | Администратор разрешает/блокирует вход |
| GET | `/api/bootstrap` | Данные, разрешённые текущему пользователю |
| POST | `/api/catalog/commands` | Изменения каталога и импорт |
| POST | `/api/attendance/lessons` | Создать занятие и зафиксировать состав |
| PUT | `/api/attendance/lessons/{id}` | Изменить тему, аудиторию, время |
| PUT | `/api/attendance/lessons/{id}/entries` | Сохранить отметки |
| POST | `/api/attendance/lessons/{id}/complete` | Завершить журнал |
| POST | `/api/attendance/lessons/{id}/reopen` | Возобновить журнал |
| POST | `/api/attendance/lessons/{id}/cancel` | Отменить открытое занятие |
| GET | `/api/attendance/lessons/{id}/history` | История, студенту только собственная |
| POST | `/api/ocr/recognize` | Загрузка и обработка фото |
| POST | `/api/ocr/jobs/{id}/confirm` | Подтверждение проверки своего OCR-задания |

Для изменяющих запросов нужен заголовок `X-CSRF-TOKEN` с токеном текущей сессии.
После входа токен получается заново. `X-Lms-Demo-User` и самодельный JWT не дают доступа.
Чужие операции возвращают 403, отсутствие сессии 401, устаревшая версия 409.

## Что нужно для МИФИ

Старый `omelea-dev-lms/Server` не включён в новый вход. У него отдельные
идентификаторы пользователей, устаревшее хеширование паролей и небезопасная
передача JWT в URL на произвольный `redirectUri`. Этот путь не используется.

Для настоящего вузовского входа нужны:

1. Подтверждённые адреса CAS и правила регистрации приложения у МИФИ.
2. Разрешённый фиксированный HTTPS callback вашего сервера.
3. Тестовая вузовская учётная запись и сведения о возвращаемых атрибутах.
4. Серверная проверка CAS ticket и связь внешнего идентификатора с `PersonID`.
5. Отдельное назначение прав в LMS: успешный вход не должен автоматически давать роль администратора.

Пароль вузовского аккаунта в чат присылать не нужно. Проверка провайдера не выполнена;
кнопка, создающая впечатление рабочего внешнего входа, убрана.

## Границы MVP

Состав фиксируется **на момент создания занятия**, не восстанавливается автоматически
по историческим датам зачисления. Полноценное расписание, семестры, смена учебного
года в интерфейсе и восстановление отменённого занятия пока не реализованы.
Создаваемые через панель курсы по умолчанию относятся к 2026 году; занятие использует
активный год курса из БД. Отменённые занятия исключаются из показателей мониторинга.

Статистика пока вычисляется клиентом по отфильтрованным сервером данным.
Для больших объёмов потребуются серверные агрегаты, пагинация и оптимизация выборок.
Вне области работ: старые демонстрационные задания, тесты, материалы, оценки,
календарь и нормализованные академические ведомости `CourseReport`.

Это MVP, не заявление о готовности к публичной эксплуатации. До публикации нужны
HTTPS, ограниченная роль БД, безопасное хранение ключей и конфигурации, проверенное
восстановление резервных копий, нагрузочная проверка и правила хранения фото.
Ключи cookie находятся в `.local/auth-keys`, на Windows защищены DPAPI текущего
пользователя. На другом сервере пользователи входят заново; ключи нельзя помещать
в Git. Для новой production-БД первый пароль задаётся `Auth__BootstrapAdminPassword`,
без создания файла тестовых паролей; после входа его потребуется сменить.

## Объём всей LMS

Ориентировочно минимальный бэкенд всей LMS потребует ещё нескольких сопоставимых
модулей, в сумме порядка **3–5 объёмов модуля посещаемости**. Это оценка требований,
не соотношение числа строк. Готовые вход, каталог и доступ к БД можно использовать повторно.
Основной дополнительный объём: материалы и файлы, сдача/проверка работ, тестирование
с попытками, правила оценивания, ведомости с реальными студентами, календарь и уведомления.
